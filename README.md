# Garissa County Public Investment Management (PIM) Projects Dashboard

Public, GIS-based register of County Government of Garissa projects with a citizen feedback mechanism
(KDSP II, Key Result Area 3, DLI 7). Static site: no build step, no licence fees, runs on any web server.

## What is in it

| Page | Purpose |
|---|---|
| Home | Totals by status and budget, KDSP II investment project, guided tour |
| Map | Interactive map: county, sub-county and ward boundaries; street, hybrid, satellite, light, terrain and dark base maps; click a ward or sub-county to filter |
| Projects | Search and filter by name, ward, sub-county, department, status, financial year, funding source; Excel and PDF downloads |
| Analytics | Totals by status, sub-county, department, year and funding source; KDSP II stock-take bands; stalled projects |
| Library Project | Phase and requirements tracker for the County Library, ICT & Innovation Centre and Civic Auditorium, site map, project grievance desk (GRM) |
| Feedback | Enquiry, complaint, compliment or suggestion; reference number; automatic acknowledgement; 7-day response standard |
| KDSP II | DLI 7 checklist, data-completeness score, APA 3 recommendations and how each is addressed, one-click reports |
| Help | Questions and answers in English, Kiswahili and Af-Soomaali |

Accessibility: skip link, full keyboard use, screen-reader labels, text size, high contrast, easy-reading
spacing, stop animations, read-aloud. Works offline after the first visit; feedback written offline is sent
when the connection returns.

## Data

`data/projects.json` is generated by `tools/build_data.py` from:

1. `GC Project _ FY 2018 - 22.xlsx` (KDSP II Project Stock-taking Template, 104 records)
2. `Stalled projects.xlsx` (17 records)
3. `data/manual_projects.json` (KDSP II investment project and published FY 2026/27 tenders, shown as Proposed)

To update: edit the workbooks or `manual_projects.json`, then run `bash tools/rebuild.sh` from this folder
(set `GIS_DIR` to the folder holding the county GIS layers if it is not `~/garissa_local_workdir`).

Locations: records without surveyed GPS are placed at a named landmark where the title gives one, otherwise
inside the ward (near its main settlement), otherwise inside the sub-county. Each record carries a
`loc_precision` label that the public sees. Replace `lat`/`lon` with surveyed points as they are captured.

Library tracker: edit `data/library_tracker.json` (`current_phase`, and each requirement's `status`:
`ready`, `progress` or `pending`).

## Feedback delivery (`js/config.js`)

- `formsubmit` (default, for GitHub Pages): messages are relayed to feedback@garissa.go.ke and the citizen gets an
  automatic acknowledgement. **The first message sends a one-time activation email to feedback@garissa.go.ke;
  open it and confirm, otherwise nothing is delivered.** This is a third-party relay, suitable for staging.
- `php` (for the County server): `api/feedback.php` stores every message in a database (`api/schema.sql`),
  emails the feedback desk and sends the acknowledgement; `api/report.php` produces the system-generated
  feedback report (evidence code 007_DL7_1.4.1). Edit `api/settings.php` first and change `REPORT_KEY`.
- `mailto`: opens the citizen's email app. Also the automatic fallback if sending fails.

## Hosting

GitHub Pages: push this folder to a repository, then Settings > Pages > Deploy from branch > `main` / root.
County server: copy the folder to the web root (for example `projects.garissa.go.ke`), set
`FEEDBACK_MODE: 'php'`, and link it from the home page of www.garissa.go.ke.

## Translations

Interface text is in `js/i18n.js`. Kiswahili and Af-Soomaali should be reviewed by County language officers
before go-live; correct any line by editing its key.
